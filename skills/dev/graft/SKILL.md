# Graft (Context Graph Engine)

`graft/` хранит граф кодовой базы: компактные markdown-узлы с описанием логики компонентов, точными диапазонами строк `file:line`, а также граф вызовов и зависимостей (who-calls-what). 
Запрос к узлу обходится всего в пару сотен токенов, тогда как ручное чтение исходников расходует тысячи токенов и упускает косвенные связи.

Все команды работают локально ($0), не требуют API-ключей и возвращают ответ быстрее чем за секунду.

---

## ⚡ Установка и запуск

- **Через npx (без установки):**
  ```bash
  npx @nanonets/graft <command>
  ```
- **Глобальная установка:**
  ```bash
  npm install -g @nanonets/graft
  ```
- **Инициализация графа в проекте:**
  ```bash
  graft build
  ```

## 🛠 Ключевые команды и инструменты

### 1 · `graft ask "<question>" --source`: Поиск и понимание архитектуры (Default)
Ранжированный поиск по графу с автоматической маршрутизацией между узлами описания и графом связей. Возвращает топ результатов с точными `file:line`.
- `--source` выводит суть (crux, ≤8 строк кода) каждого определения прямо в результат, исключая необходимость дополнительно открывать файл.
- `--in <path>` ограничивает поиск поддеревом; `-n N` задает лимит выдачи (по умолчанию 8).
- **Когда использовать:** для концептуальных или локационных вопросов («как устроена авторизация», «где обрабатывается rate-limiting», «что собирает pipeline»).

### 2 · `graft grep "<pattern>"`: Исчерпывающий поиск по графу
Регулярное выражение (или `--fixed` для точного совпадения) по всем проиндексированным файлам. Результаты **сгруппированы по внешнему символу** и отранжированы по степени связности.
- **Когда использовать:** когда требуются все вхождения (все места вызова, все использования константы, все провайдеры).
- Используйте **короткое имя символа**, а не длинную сигнатуру метода.

### 3 · `graft skeleton <file>`: Сигнатуры API файла
Обзор сигнатур файла (каждая функция, метод, тип со своим диапазоном строк) объемом ~200 токенов (~в 10 раз дешевле чтения файла целиком).
- **Когда использовать:** когда нужно понять «что есть в этом файле / что можно вызвать» перед правкой.

### 4 · `graft callers <symbol>`: Точный граф вызовов и связей
Предрассчитанные ребра графа вызовов/ссылок, а не текстовый поиск.
- `--direction in` (по умолчанию): **кто вызывает/ссылается** на символ. Запускать перед переименованием, удалением или изменением сигнатуры.
- `--direction out`: **что сам этот символ вызывает** (callees).
- `--depth N`: транзитивный обход на N шагов для оценки зоны поражения (**blast radius**); `--depth 2` стандартно для проверки «что сломается, если изменить это».
- `--depth all`: **полное связное замыкание** (entire connected closure) — все файлы и модули, достижимые через ребра. Незаменимо перед рефакторингом или мультифайловыми правками.

### 5 · `graft map`: Обзор архитектуры незнакомого репозитория
Экономный по токенам тур: кластеры директорий, хабы внутри директорий и глобальные горячие точки (hotspots).
- **Когда использовать:** при знакомстве с новой кодовой базой или запросе «объясни архитектуру».

### 6 · Жизненный цикл: `graft build` / `graft check`
Каждый инструмент выше автоматически обновляет граф перед ответом. Запускать `build` после каждого редактирования не требуется.
- `graft build` — полная пересборка графа.
- `graft check` — валидация актуальности директории `graft/` (для CI).

## 🧭 Сценарии выбора инструмента

| Ситуация / Задача | Инструмент | Число вызовов |
| :--- | :--- | :--- |
| Онбординг / «объясни архитектуру» | `graft map`, затем чтение карточек хабов | 1 |
| Понимание потока («как работает X») | `graft ask "<flow>" --source` | 1 |
| Поиск места для внесения изменений | `graft ask "where is <behavior>" --source` | 1 |
| Редактирование известного символа | `graft grep "<symbol>"`, переход к `file:line` | 1 |
| Переименование / удаление / смена сигнатуры | `graft callers <sym> --depth 2` перед правкой | 1 |
| Рефакторинг / правка нескольких файлов | `graft callers <sym> --depth all` (полная карта связей) | 1 |
| «От чего зависит этот модуль/функция?» | `graft callers <sym> --direction out` | 1 |
| Поиск всех вхождений константы/паттерна | `graft grep "<literal>"` | 1 |
| «Какое API у этого файла?» | `graft skeleton <file>` | 1 |
| Отладка бага в модуле X | `graft ask "<symptom>" --source`, затем `callers` | 1–2 |
| Оценка риска PR перед мерджем | `graft callers <changed sym> --depth 2` | 1 на символ |

## 🔌 MCP Инструменты (при подключении Graft MCP)
Если подключен MCP-сервер Graft, доступны эквивалентные нативные инструменты:
- `graft_find_code` (аналог `ask`)
- `graft_find_all` (аналог `grep`)
- `graft_file_api` (аналог `skeleton`)
- `graft_trace_calls` (аналог `callers` с параметрами `direction` и `depth`)
- `graft_repo_map` (аналог `map`)
- `graft_check_freshness` (аналог `check`)
