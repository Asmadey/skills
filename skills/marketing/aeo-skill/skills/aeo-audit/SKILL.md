# Полный аудит

Справочники лежат в навыке `aeo`: `../aeo/references/` (доказательная база, движки, мифы, методика оценки). Скрипты: `../aeo/scripts/`.

## Шаг 0. Вводные

Узнай (или определи по сайту) и зафиксируй в начале отчёта:

- URL, название бренда и его варианты написания.
- Тип бизнеса: SaaS/B2B, ecommerce, локальный, издатель, YMYL.
- 3–5 конкурентов и 5–10 «денежных» запросов. Если пользователь не дал, предложи свои и отметь, что это допущение.
- Какие доступы есть: Search Console, Bing Webmaster Tools, GA4, логи сервера. Нет доступа — блок помечается `НЕ ПРОВЕРЕНО`.

## Шаг 1. Сбор фактов

```bash
python3 ../aeo/scripts/check_access.py <url>
python3 ../aeo/scripts/page_audit.py <url> --brand "<бренд>" --json     # главная
python3 ../aeo/scripts/page_audit.py <url-страницы> --brand "<бренд>"   # 3–5 ключевых страниц
```

Ключевые страницы: главная, цены, главный продукт или услуга, лучшая статья, «О компании». Если сеть из оболочки закрыта, получи HTML через WebFetch или попроси файл и запусти с `--file`.

## Шаг 2. Семь блоков

Если доступен запуск субагентов и пользователь не возражает, раздай блоки параллельно агентам `aeo-technical`, `aeo-content`, `aeo-entity`, `aeo-offpage`. Иначе пройди последовательно по под-навыкам:

| Блок | Под-навык | Минимум проверок |
|---|---|---|
| 1. Доступность | `aeo-technical` | robots, ответы ботам, слова и ссылки в сыром HTML, размер, стены перед контентом, Bing |
| 2. Извлекаемость | `aeo-content` | первые 200 символов, доля чистых пассажей, заголовки-вопросы, таблицы |
| 3. Сущность | `aeo-entity` | четыре теста распознавания, совпадение фактов, schema и sameAs |
| 4. Сторонний след | `aeo-offpage` | какие домены цитируют модели по денежным запросам и есть ли там бренд |
| 5. Доказательства | `aeo-content` | собственные данные, авторы, проверяемость утверждений |
| 6. Свежесть | `aeo-refresh` | даты, устаревшие факты, тип угасания |
| 7. Измеримость | `aeo-measure` | набор промптов, каналы GA4, отчёты AI в GSC и Bing |

## Шаг 3. Живой замер

Прогони 10–20 промптов из `../aeo/references/prompt-set.md` минимум в двух системах, каждый по три раза, и запиши исходы через `visibility_tracker.py`. Если доступа к ассистентам нет, выдай пользователю готовый список промптов и таблицу для заполнения; блок 7 оценивай не выше 2.

## Шаг 4. Оценка

По `../aeo/references/scoring.md`: балл 0–4 за блок, веса по типу бизнеса, стоп-фактор при недоступности ботам. Рядом с каждым баллом — одно предложение обоснования с доказательством.

## Шаг 5. Отчёт

```markdown
# AEO-аудит: <домен> — <дата>
**Оценка: NN/100** (<вывод по шкале>)
## Главное
- 3 проблемы, которые сильнее всего мешают
- 3 действия на ближайшие две недели
## Оценка по блокам            (таблица: блок | балл | вес | вклад | обоснование)
## Находки                     (таблица: приоритет | находка | доказательство | действие | проверка | источник)
## Что говорят AI-системы      (цитаты ответов с датой и движком, ошибки в фактах)
## План на 90 дней             (по `aeo-plan`: недели 1–2, 3–6, 7–12)
## Не проверено                (что и какой доступ нужен)
```

## Правила качества

- Находка без доказательства в отчёт не попадает.
- Симптом отделяй от причины: «12 000 дублей» — наблюдение; находка — что их порождает.
- Формулируй нужный результат, а не способ реализации, если не знаешь стек сайта.
- Не больше 15 находок; остальное — в приложение. Первыми идут те, что затрагивают страницы с выручкой [S097, S111].
- Проверь выводы по `../aeo/references/myths.md`, прежде чем отдавать отчёт.
