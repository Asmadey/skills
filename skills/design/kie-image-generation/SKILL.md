# Генерация картинок через kie.ai

Один API на десятки моделей (nano banana, Flux-2, GPT Image, Seedream и т.д.). Работа
асинхронная: создаёшь задачу, опрашиваешь её, забираешь файл.

## When to Use

- Нужно сгенерировать иллюстрации, превью или обложки программно, без человека в чате.
- Нужно перегенерировать картинку под другой размер/пропорцию.
- Нужно проверить баланс кредитов или состояние задачи.

## Ключ

`KIE_API_KEY` в окружении либо первая строка `~/.hermes/keys/kie.txt` (`chmod 600`).
Ключ берётся на `https://kie.ai/api-key`. В чат, логи и коммиты ключ не писать.

## API (проверено по docs.kie.ai, 02.11.2026)

База `https://api.kie.ai`, заголовок `Authorization: Bearer <key>`.

| Метод | Путь | Что |
|---|---|---|
| GET | `/api/v1/chat/credit` | баланс → `{"code":200,"data":100.5}` |
| POST | `/api/v1/jobs/createTask` | создать задачу → `data.taskId` |
| GET | `/api/v1/jobs/recordInfo?taskId=…` | состояние и результат |
| POST | `/api/v1/common/download-url` | временная ссылка на файл (живёт 20 минут) |

Тело создания задачи:

```json
{"model": "google/nano-banana",
 "input": {"prompt": "…", "aspect_ratio": "3:2", "output_format": "png"}}
```

Состояния в `data.state`: `waiting` → `queuing` → `generating` → `success` | `fail`.
Результат лежит в `data.resultJson` — это **строка с JSON**, внутри `resultUrls: [...]`.

Модели: `google/nano-banana` (Gemini 2.5 Flash Image, дешёвая и быстрая),
`google/nanobanana2`, `google/nano-banana-pro`, `google/nano-banana-2-lite`,
`flux2/*`, `gpt/*`, `seedream/*`. `aspect_ratio`: `1:1`, `3:2`, `4:3`, `16:9`, `9:16`,
`2:3`, `3:4`, `4:5`, `5:4`, `21:9`, `auto`.

## Модели GPT Image 2.5 (основная для иллюстраций)

| Модель | Что |
|---|---|
| `gpt-image-2-5-flare-text-to-image` | текст → картинка, мягкий объёмный стиль |
| `gpt-image-2-5-sunburst-text-to-image` | текст → картинка, более графичный и контрастный |
| `gpt-image-2-5-*-image-to-image` | по референсам, `input_urls` до 16 URL |

Параметры в `input`: `prompt` (до 20 000 символов), `aspect_ratio` (`auto` по умолчанию,
`1:1`, `3:2`, `2:3`, `4:3`, `3:4`, `16:9`, `9:16`, `21:9`, `27:16`, `16:27`, `9:8`, `8:9`;
последние четыре — только на 1K), `resolution` (`1K` | `2K` | `4K`), `background`
(`transparent` | `opaque` | `auto`), `input_urls` для image-to-image.

**Правило проекта: всегда `resolution: "1K"`**, размер подбирается кадрированием под
место на сайте. Выход — всегда PNG; при `background: "transparent"` приходит с альфой.

Прозрачный фон снимает главную головную боль: не надо подгонять цвет фона под
`#0b0d12` и ловить шов по краю кадра. Но только если страница действительно тёмная там,
где стоит картинка. При прозрачном фоне **нельзя** гонять `match_background()` — он
переводит кадр в RGB и убивает альфу.

## Скрипт

`scripts/kie_image.py` рядом со скиллом (и рабочая копия в `~/.hermes/profiles/coder/scripts/`).
Создаёт, ждёт, скачивает; умеет проверять баланс и статус.

Опубликованная копия скилла — репозиторий `Asmadey/skills`, путь
`skills/design/kie-image-generation/` (профильная папка `media/` — только локальная
раскладка; в библиотеке всё, что рисует картинки, лежит в `design/`). Правишь скрипт
здесь — перекопируй и запушь туда же в том же ходе: две копии расходятся молча, и
читатель получает уже починенные баги.

```bash
python3 ~/.hermes/profiles/coder/scripts/kie_image.py --credits
python3 ~/.hermes/profiles/coder/scripts/kie_image.py -p "<промпт>" -a 3:2 \
  -s 1200x800 -o public/assets/ozvuchka/hero.webp
python3 ~/.hermes/profiles/coder/scripts/kie_image.py --status task_abc123
```

Приёмка пачкой (формат, размер, фон/альфа, контактный лист) — `scripts/check_image.py`:

```bash
python3 check_image.py public/assets/**/*.webp --bg 11,13,18 --expect 1200x800 --sheet /tmp/sheet.png
```

`-s 1200x800` делает cover-кадрирование и пишет webp — ровно то, что нужно для сайта
(в коде размеры заданы жёстко: 1200×800 для иллюстраций, 640×480 для превью).
GPT Image 2.5 всегда отдаёт PNG, поэтому перекодирование в webp не опция, а обязательный шаг
конвейера; при `background: "transparent"` альфа переживает перекодирование (режим `RGBA`),
и это проверяется после записи. Дополнительно: `--resolution 1K|2K|4K`,
`--background transparent|opaque|auto`, `--out-suffix` для сравнения вариантов.

## Ловушки

- **Ошибки приходят с HTTP 200.** Смотреть `code` в теле: `401` — ключ, `402` — нет
  кредитов, `422` — задача не существует или принадлежит другому аккаунту. Проверка
  только по HTTP-статусу даёт «успех» на проваленной задаче.
- **`resultJson` — строка, не объект.** `json.loads(data["resultJson"])["resultUrls"][0]`.
  Прямой доступ по ключам даёт `TypeError`.
- **Ссылка из `resultUrls` — не вечная.** Сами файлы kie хранит 14 дней, а
  `common/download-url` выдаёт ссылку на 20 минут: скачивать сразу, не откладывать в очередь.
- **`callBackUrl` для продакшена, опрос — для скриптов.** Опрос с паузой 3 → 10 с;
  видео-задачи живут дольше 10 минут, поэтому таймаут по умолчанию 300 с надо поднимать явно.
- **Лимит 20 новых задач за 10 секунд** на аккаунт; при превышении `429`, и такой запрос
  в очередь не попадает. Для пакета из 6 картинок пауза 1 с между createTask достаточна.
- **Кириллица на картинке.** Модель рисует русский текст с ошибками; если подписи
  нужны, их место в HTML, а не в изображении. В промпт добавлять `no text, no letters`.
- **Фон: сначала прозрачность, потом подгонка.** `background: "transparent"` у GPT Image 2.5
  отдаёт кадр с альфой, и подгонять цвет не нужно вовсе — картинка ложится на страницу без
  шва. Аддитивная подгонка к `#0b0d12` остаётся только для `opaque`-кадров и старых моделей:
  она сдвигает фон на 2–3 уровня, но не убирает светлый «пол» или блик — широкий градиент
  остаётся, и на тёмной странице виден прямоугольник.
- **Модель дорисовывает сцену, если её не запретить.** Продуктовые промпты тянут «пол», линию
  горизонта, отражение и блик в углу. `no text` тут не спасает: нужны явные
  `no floor, no table surface, no horizon line, no reflection, no light glare in the corners,
  no vignette` плюс «объекты светятся сами, фона нет».
- **Не называть то, чего в кадре быть не должно.** Формулировка «abstract … mountain thumbnail»
  рисует фотографию гор внутри абстрактного интерфейса: модель читает существительное, а не
  прилагательное рядом с ним. Содержимое экрана описывать как «soft blue-violet gradient haze»,
  а конкретику запрещать отдельно (`no landscape, no photograph, no sky`).
- **Сравнивать модели до пакета, а не после.** Две модели на одном промпте стоят два кадра,
  перегенерация шести — двенадцать. Гонять сравнение на самой простой по композиции картинке
  и выбирать по соответствию существующему стилю сайта, а не по «нравится/не нравится».
- **Цена видна только после кадра.** `creditsConsumed` приходит в `recordInfo` каждого задания:
  nano-banana ≈4 кредита за кадр, GPT Image 2.5 ≈6. Баланс печатать до и после пакета, чтобы
  отчёт был про факт, а не про ожидание.
- **`--out-suffix=-flare`, а не `--out-suffix -flare`.** argparse считает значение,
  начинающееся с дефиса, опцией и падает с `expected one argument`.

## Приёмка результата

1. Файл существует и нужного размера (`PIL.Image.open(path).size`).
2. **Фон проверяется машинно, а не глазами.** Два вида брака: модель дорисовывает светлый
   «пол» / блик в углу (тогда смотреть отклонение цвета по рамке кадра от целевого) или
   игнорирует `background: transparent` (тогда проверять альфу углов). Оба чека — 5 строк
   на PIL, и оба ловят дефект раньше человека.
3. **Прозрачный кадр нельзя оценивать по самому файлу.** Просмотрщики и vision-инструменты
   показывают альфу на белом — картинка выглядит так, будто у неё белый фон, хотя фон
   прозрачный. Перед просмотром наложить кадр на цвет страницы
   (`Image.alpha_composite(bg, im)`) и смотреть результат: иначе начинается борьба с
   несуществующим дефектом и правится здоровый кадр.
4. **Смотреть набором, а не по одному.** Контактный лист 3×2 на фоне страницы (PIL:
   `thumbnail` + `alpha_composite`) показывает то, чего не видно в отдельном файле: разные
   силуэты, выпадающий стиль, слабую композицию. Решение «годится / не годится» принимать
   по листу, а в отдельном файле — только досматривать детали.
5. Превью читается в мелком размере: уменьшить до 320 px и посмотреть глазами — на этом
   размере детали исчезают, силуэт должен остаться понятным.
6. Сравнивать с *существующими* картинками сайта, а не с абстрактным «красиво»: если на
   старых превью неоновый bloom и объект занимает 80 % кадра, а новый — серый кубик в
   центре пустоты, он выбивается из ряда, даже если сам по себе хорош.
7. Для сайта: пересобрать страницу, прогнать `verify-out` — он сверяет хеш в `?v=` с
   содержимым файла и падает, если адрес картинки выведен без `versioned()`.
