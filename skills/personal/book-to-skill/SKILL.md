# Конвертер «Книга в Навык» (Book-to-Skill Converter)

Превращает книги и объемные документы в практические навыки для ИИ-агентов путем извлечения структуры, а не пересказа содержания.

---

## 🇷🇺 Языковой протокол (Вывод на русском языке)

**КРИТИЧЕСКИ ВАЖНОЕ ПРАВИЛО:**
- **Все создаваемые файлы навыка** (`SKILL.md`, файлы глав `chapters/ch*.md`, `glossary.md`, `patterns.md`, `cheatsheet.md`), а также все отчеты, диалоги и вопросы пользователю **ДОЛЖНЫ ГЕНЕРИРОВАТЬСЯ НА РУССКОМ ЯЗЫКЕ**, независимо от того, на каком языке написана исходная книга (английский, немецкий, русский и др.).
- **Сохранение авторской точности (двуязычная терминология):** Названия фреймворков, ментальных моделей и ключевых понятий формулируются на русском языке с обязательным указанием оригинального термина в скобках для точного поиска и кросс-ссылок (например: *«Пять Почему (The 5 Whys)»*, *«Закон Литтла (Little's Law)»*, *«Паттерн Сага (Saga Pattern)»*).
- Исходный программный код, технические идентификаторы, команды CLI и пути к файлам остаются в оригинале.

---

## Философия

Книги содержат кристаллизованный опыт: проверенные временем фреймворки, принципы и методы. Этот навык переносит эти знания в формат, который агент (Antigravity, Claude Code, Amp) может многократно применять в реальной работе.

**Извлекайте структуру, а не саммари.** Навык — это не школьный реферат по книге, а прикладной инструментарий:
- **Именованные фреймворки** (ментальные модели с четкой областью применения).
- **Прикладные принципы** (правила, направляющие принятие инженерных и управленческих решений).
- **Техники и методики** (пошаговые алгоритмы действий).
- **Анти-паттерны** (чего следует избегать и почему).
- **Калибровка мышления автора** (как автор рассуждает и оценивает компромиссы).

**Сохраняйте авторскую точность.** У фреймворков есть конкретные названия не просто так. «Пять Почему (The 5 Whys)» нельзя заменять на «спроси почему несколько раз». Фиксируйте точные авторские формулировки.

**Разделяйте глубину по уровням (L1 / L2 / L3).** Простая книга $\rightarrow$ компактный навык. Сложный фундаментальный труд с 10+ концепциями $\rightarrow$ трехуровневый навык со справочниками и главами, загружаемыми по требованию.

## Режимы работы

Навык поддерживает 4 сценария в зависимости от запроса пользователя:

### 1. Полная конвертация (По умолчанию)
**Триггер:** Пользователь передал путь к файлу/папке без специальных уточнений.
**Действие:** Выполнить все шаги (Шаги 0–10).
**Результат:** Готовый навык с `SKILL.md`, `chapters/`, `glossary.md`, `patterns.md`, `cheatsheet.md` на русском языке.

### 2. Только анализ (Analyze Only)
**Триггер:** Пользователь говорит: «проанализируй», «только извлеки структуру», «покажи отчет перед генерацией».
**Действие:** Выполнить Шаги 0–3, сформировать структурированный отчет об извлечении (найденные фреймворки, принципы, главы) и остановиться БЕЗ генерации файлов навыка.
**Результат:** Аналитический отчет для согласования с пользователем.

### 3. Генерация по готовому анализу
**Триггер:** Пользователь передал ранее согласованные заметки/отчет анализа.
**Действие:** Пропустить Шаги 0–3, взять предоставленный анализ как входные данные и запустить Шаги 4–10.
**Результат:** Файлы навыка на основе готового анализа.

### 4. Обновление / Дополнение (Update / Fold-in)
**Триггер:** Пользователь передает новые материалы (статьи, новые издания, дополнительные главы) для уже существующего навыка.
**Действие:** Выполнить Шаги 0, 1, 1.5, 2, затем перейти к разделу **Update / Fold-in Workflow** для объединения нового контента со старым.
**Результат:** Обновленный навык с дополненными главами, объединенным глоссарием и обновленными индексами.

## Расположение навыков

Конвертер сохраняет создаваемый навык по приоритету:
1. Каталог навыков текущего проекта: `skills/<skill-name>/` (или `.agents/skills/<skill-name>/`)
2. Глобальный каталог Claude Code: `~/.claude/skills/<skill-name>/`
3. Глобальный каталог агентов: `~/.config/agents/skills/<skill-name>/`

По умолчанию в PersonalOS навык создается в директории проекта: `skills/<skill-name>/`.

Убедитесь, что среди `INPUT_PATHS` есть хотя бы один поддерживаемый файл (`.pdf`, `.epub`, `.docx`, `.txt`, `.md`, `.markdown`, `.rst`, `.adoc`, `.html`, `.htm`, `.rtf`, `.mobi`, `.azw`, `.azw3`).

## Шаг 1.5 — Определение типа контента

Перед извлечением спросите пользователя (на русском языке):

> «Какой тип контента преобладает в этих источниках? Это поможет выбрать оптимальный метод извлечения:
>
> 1. **Технический** — содержит блоки кода, таблицы, математические формулы, архитектурные диаграммы (книги по программированию, научные статьи, спецификации).
> 2. **Текстовый** — преимущественно связанный текст, минимум таблиц и кода (менеджмент, продуктивность, психология, бизнес-литература).
> 3. **Затрудняюсь ответить** — использовать быстрый базовый метод с контролем качества.»

Значения:
- Вариант 1 $\rightarrow$ `BOOK_TYPE=technical` (используется Docling для таблиц и формул).
- Вариант 2 или 3 $\rightarrow$ `BOOK_TYPE=text` (быстрый текстовый экстрактор).

## Шаг 2 — Извлечение текста

Запустите скрипт извлечения:

```bash
SCRIPT_PATH=""
for candidate in \
  "skills/book-to-skill/scripts/extract.py" \
  "$HOME/.claude/skills/book-to-skill/scripts/extract.py" \
  ".agents/skills/book-to-skill/scripts/extract.py"
do
  if [ -f "$candidate" ]; then
    SCRIPT_PATH="$candidate"
    break
  fi
done

python3 "$SCRIPT_PATH" $INPUT_PATHS --mode <BOOK_TYPE> --install-missing ask
```

Результат выполнения:
- `<tempdir>/book_skill_work/full_text.txt` — объединенный текст всех источников.
- `<tempdir>/book_skill_work/metadata.json` — метаданные (страницы, слова, токены, список источников).

## Шаг 2.6 — Потоковая работа с большими книгами (> 50k токенов)

Для книг объемом более 50k токенов **не загружайте весь файл `full_text.txt` в контекст целиком**! Используйте точечный поиск и срезы:

```bash
# Проверка размера
wc -w "$FULL_TEXT_PATH"

# Поиск границ глав без загрузки всей книги
grep -n -E "^\s*(Chapter|CHAPTER|Глава|ГЛАВА)\s+[0-9]+" "$FULL_TEXT_PATH" | head -40

# Извлечение только нужной главы (строки от start до end)
sed -n '<start>,<end>p' "$FULL_TEXT_PATH"

# Проверка упоминания термина перед добавлением в индекс
grep -c -i "DDD\|CQRS" "$FULL_TEXT_PATH"
```

## Шаг 8 — Генерация вспомогательных файлов (на русском языке)

### 1. `glossary.md`
Создайте `$SKILLS_HOME/<skill_name>/glossary.md`:
- Все значимые термины книги в алфавитном порядке на русском языке.
- Формат: `**Термин на русском (Original Term)** — определение (Гл. N)`
- Лимит: до 1 500 токенов.

### 2. `patterns.md`
Создайте `$SKILLS_HOME/<skill_name>/patterns.md`:
- Все прикладные техники, шаблоны проектирования и алгоритмы из книги.
- Формат:
  ```markdown
  ## Название паттерна (Original Pattern Name)
  **Когда использовать**: ...
  **Как применять**: ...
  **Компромиссы и риски (Trade-offs)**: ...
  ```
- Лимит: до 2 000 токенов.

### 3. `cheatsheet.md`
Создайте `$SKILLS_HOME/<skill_name>/cheatsheet.md`:
- Шпаргалка: матрицы принятия решений, контрольные списки (чеклисты), правила быстрого выбора.
- Контент, который поместился бы на одну страницу-памятку.
- Лимит: до 1 000 токенов.

## Процедура обновления (Update / Fold-in Workflow)

При добавлении новых источников к существующему навыку:
1. **Анализ текущей структуры:** Прочитать существующий `SKILL.md`, список глав в `chapters/` и найти максимальный номер главы.
2. **Определение ревизий и дополнений:** Понять, обновляет ли новый текст существующие главы или добавляет новые (новые нумеруются с номера `N+1`).
3. **Генерация/обновление файлов глав:** На русском языке по стандарту Шага 7.
4. **Слияние глоссария и паттернов:**
   - В `glossary.md`: добавить новые термины, отсортировать по алфавиту, для существующих терминов дополнить ссылки на новые главы.
   - В `patterns.md`: дописать новые паттерны и методы.
   - В `cheatsheet.md`: расширить таблицы сравнения.
5. **Обновление `SKILL.md`:** Актуализировать количество глав, дату генерации, дополнить таблицы указателя глав и предметный указатель.

## Правила качества (Quality Rules)

1. **Всегда генерируйте выходные материалы на русском языке** с указанием оригинальных названий терминов в скобках.
2. **Извлекайте структуру, а не пересказ** — фиксируйте формулы, правила принятия решений, алгоритмы и анти-паттерны, а не поверхностное содержание.
3. **Плотность выше полноты** — 1 000 токенов концентрированного смысла ценнее 10 000 токенов водянистых цитат.
4. **Голос практикующего инженера** — формулируйте предписания: *«Используйте X, когда Y»*, а не *«В книге автор рассказывает про X»*.
5. **Главное — в начало** — сжатие контекста обрезает конец, поэтому в `SKILL.md` самое ценное идет в первых 2 000 токенах.
6. **Никогда не копируйте сырой текст книги** — синтезируйте, структурируйте и выделяйте суть.
