# Лимиты Groq, ротация ключей и учёт бюджета

Документ описывает `scripts/groq_keys.py` — слой, через который идут **все** вызовы Groq в навыке
(диаризация, анализ, распознавание). Он же ведёт локальный учёт расхода.

## 1. Что реально ограничено

Замерено на ключе free-tier (значения отдаются в заголовках ответа):

| Модель | Ограничение | Где узнать |
| :--- | :--- | :--- |
| `openai/gpt-oss-120b`, `qwen/qwen3.8-27b`, `openai/gpt-oss-20b` | **8 000 токенов/мин** на модель | `x-ratelimit-limit-tokens` |
| те же | 1 000 запросов, окно ~1–2 мин | `x-ratelimit-limit-requests` + `x-ratelimit-reset-requests` |
| те же | **200 000 токенов/сутки** | только из текста 429: `Limit 200000, Used 198589` |
| `whisper-large-v3` | 2 000 запросов, окно ~45 с | `x-ratelimit-limit-requests` |
| `whisper-large-v3` | секунды аудио / мин и / сутки | **не отдаются вообще** |
| `qwen/qwen3.8-27b` | вход (ITPM) **7 000** токенов/мин — меньше, чем у 120b | 413 `… on input tokens per minute (ITPM): Limit 7000` |

Месячных квот у Groq нет: лимиты минутные и суточные. На Dev-tier дневных потолков нет — оплата
по токенам.

**Следствие:** остаток дневного бюджета узнать заранее нельзя — API сообщает о нём только
в момент отказа. Поэтому расход считается локально, а фактические цифры за произвольный период
смотреть в `console.groq.com/usage`.

## 2. Откуда берутся ключи

Порядок = приоритет, дубликаты отбрасываются:

1. env `GROQ_API_KEYS` / `GROQ_KEYS` — `"gsk_a,gsk_b"` (запятая, пробел, перевод строки);
2. `.env` — переменные вида `groq`, `groq2`, `groq_2`, `GROQ_KEY_3`, `GROQ_API_KEY_4`;
3. `groq_keys.txt` в корне проекта — по ключу на строку, `#` — комментарий;
4. `~/.groq_keys` — тот же формат, общий для всех проектов.

Маскирование: в логах и состоянии видны только последние 4 символа (`…I6kD`), в state-файл
ключи не пишутся — только `sha256(key)[:16]`.

## 3. Как ведёт себя при отказах

| Ответ | Классификация | Действие |
| :--- | :--- | :--- |
| 429 `tokens per day` / `requests per day` / `audio seconds per day` | `daily` | ключ помечается до ETA сброса, запрос уходит на следующий ключ |
| 429 `tokens per minute` / `requests per minute` | `minute` | ротация на другой ключ, если он свободен, иначе ожидание (≤ 90 с) |
| 413 `Request too large …` | `too_large` | ключ не меняется, модель не меняется — вызывающий дробит окно |
| 400/422 на размер запроса | `fatal` | сразу наверх, без ротации |
| 401/403 | `invalid` | ключ отключается навсегда |
| 5xx, таймауты | `transient` | экспоненциальный бэкофф, тот же ключ |

Если все ключи выгорели — поднимается `AllKeysExhausted` с ближайшим временем сброса; пайплайн
не падает с трейсбеком, а либо переключается на более дешёвую модель (`whisper-large-v3-turbo`),
либо останавливается с понятным сообщением.

## 4. Учёт расхода (ledger)

Считается **на (ключ, модель, UTC-день)**:

- `tokens_used` — фактический `usage.prompt_tokens + completion_tokens` каждого ответа;
- `audio_used` — секунды распознанного аудио (из ответа whisper, иначе из длины чанка);
- `calls`, `daily_limit`, `daily_limit_kind` — выученный лимит и его единицы.

**Проактивная проверка.** Перед запросом передаётся оценка: диаризатор — размер своего prompt,
whisper — длина чанка. Если по учёту бюджет не влезает, ключ пропускается **без отправки
запроса**:

```
🔁 [openai/gpt-oss-120b] key …I6kD: дневной бюджет не влезает (199500/200000 израсходовано) → следующий ключ
```

**Лог.** `.cache/groq_usage.jsonl`, по строке на вызов:
`{"ts", "utc_day", "key", "model", "tokens_in", "tokens_out", "audio_sec"}`.

**CLI.**

```bash
python3 scripts/groq_keys.py status    # ключи, состояние, расход за сутки, % бюджета
python3 scripts/groq_keys.py check     # живой 1-токенный прогон, снимает реальные лимиты из заголовков
python3 scripts/groq_keys.py usage 1   # расход за сутки
python3 scripts/groq_keys.py usage 30  # расход за 30 суток ("месяц")
python3 scripts/groq_keys.py reset     # очистить состояние (не лог)
```

## 5. Практические ориентиры

| Операция | Расход |
| :--- | :--- |
| Распознавание 1 часа аудио (whisper) | 3 600 аудио-секунд |
| Диаризация часовой встречи (300 сегментов, v2) | ~10 000 токенов, 2–3 вызова |
| То же на окнах по 30 сегментов (v1) | ~24 500 токенов, 11 вызовов |
| Профили + боли (часовая встреча) | ~5 000–8 000 токенов |
| Полный прогон встречи на одном ключе | 200 000/сутки ≈ **6–8 встреч** |

Главный источник перерасхода — не размер окон, а повторные прогоны: каждая переделка встречи
оплачивается целиком. Поэтому готовые части и инсайты кэшируются в JSON стенограммы, а `--force`
включает пересчёт осознанно.

## 6. Юридическая оговорка

Ротация аккаунтов ради обхода лимитов нарушает ToS Groq. Кольцо рассчитано на ключи, которые
принадлежат тебе легально: свой аккаунт, командные/организационные ключи, Dev-tier ключи.
