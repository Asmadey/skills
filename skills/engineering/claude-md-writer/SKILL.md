# Claude MD Writer

## 1. Когда использовать
- При создании новых проектов или навыков.
- Когда файлы документации (`CLAUDE.md`, `AGENTS.md`, `SKILL.md`) превышают лимиты.
- При изменении архитектуры проекта или стека технологий.

## 2. Валидация и ограничения
- [ ] **Лимит Foundation**: `AGENTS.md` / `CLAUDE.md` < 200 строк.
- [ ] **Лимит Component**: Каждый `SKILL.md` < 500 строк.
- [ ] **Приоритет**: Критические правила всегда в самом верху файла.
- [ ] **Модульность**: Специфичные инструкции выносятся в `.claude/rules/` или папки навыков.

## 3. Workflow (3-уровневая система)
- **Tier 1: Foundation (AGENTS.md)** — Глобальные правила, команды сборки, архитектурный обзор. Всегда в контексте.
- **Tier 2: Component (skills/*/SKILL.md)** — Специфика конкретного модуля или инструмента. Загружается только при работе с ним.
- **Tier 3: Feature** — Описание фичи, ко-локация с кодом.

### Алгоритм оптимизации:
1. **Анализ**: Проверить количество строк в главном файле.
2. **Экстракция**: Вынести узкоспециализированные данные (SQL, API, Deploy) в отдельные файлы.
3. **Ссылки**: Использовать синтаксис `@file` для указания на модульную документацию.
4. **Валидация**: Убедиться, что в главном файле остались только правила, применимые к ЛЮБОЙ задаче.

## 4. Инструкции (Степени свободы)
### Heuristics (Высокая свобода)
- Используй здравый смысл при разделении: если правило нужно только для 1 из 10 задач, выноси его.
- Отдавай приоритет краткости (Conciseness) над избыточностью.

### Templates (Низкая свобода)
При создании нового правила используй формат:
```markdown
### [Заголовок правила]
**Почему**: [Обоснование]
**Что делать**: [Четкая инструкция]
```

## 5. Ресурсы
- `rules/` — шаблоны для специфичных доменов (db.md, api.md).
- `examples/` — примеры "идеальных" CLAUDE.md.
