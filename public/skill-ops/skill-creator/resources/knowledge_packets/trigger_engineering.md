# Trigger Engineering & Negative Triggers

## Почему это важно?
Агент решает, загружать ли навык в контекст, основываясь ТОЛЬКО на YAML-описании (`description`). Если описание слишком общее, навык будет "засорять" контекст тогда, когда он не нужен.

## Правило "Что и Когда"
Хорошее описание отвечает на два вопроса:
1. **Что** делает навык? (Functional)
2. **Когда** его нужно вызвать? (Situational)

*Плохо:* "Инструмент для работы с Google Таблицами."
*Хорошо:* "Автоматизирует выгрузку лидов из n8n в Google Таблицы. Используйте, когда нужно синхронизировать данные CRM или создать отчет по новым заявкам."

## Negative Triggers (Отрицательные триггеры)
Это явные запреты. Они помогают агенту ОТСЕКАТЬ лишнее.
Всегда указывай их в разделе `When to use`.

Примеры:
- "Не использовать для простых SQL-запросов."
- "Не активировать, если пользователь просит только текст без генерации графики."
- "Игнорировать при обсуждении фронтенд-дизайна (использовать только для бэкенда)."

## Формат в SKILL.md
```markdown
## 1. Когда использовать
- [Положительный триггер 1]
- [Положительный триггер 2]
- **Negative Triggers:**
  - Не использовать для [Ситуация X]
  - Игнорировать, если [Условие Y]
```
