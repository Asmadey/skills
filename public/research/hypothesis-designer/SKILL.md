# Hypothesis Designer

## 1. Когда использовать
- При анализе оттока (churn) или низких конверсий.
- Перед запуском новой фичи или продукта.
- Для проверки предположений о поведении аватаров (сегментов).

## 2. Форматы гипотез (согласно базе знаний)

### Класс А: Гипотеза Проблемы (Problem Hypothesis)
**Формула:** "Мы считаем, что **[как много/часто] [роль]**, при **[решении задачи]** сталкиваются с **[проблемами]**, из-за **[причины]**, и теряют при этом **[что/сколько]**."

### Класс Б: Гипотеза Решения (Solution Hypothesis)
**Формула:** "Мы считаем, что **[клиенты]** смогут решить **[проблему]**, возникающую при **[решении задачи] [каким образом]** благодаря **[возможностям продукта]**, получат при этом **[выгоды]**."

## 3. Workflow (Checklist)
- [ ] **Шаг 1: Выбор аватара и JTBD.** Определить роль (Аватар) и конкретную "работу" (Job Story), которую он выполняет.
- [ ] **Шаг 2: Формулировка Проблемы.** Создать гипотезу по формуле Класса А. Обязательно указать потери (деньги, время, ресурс).
- [ ] **Шаг 3: Формулировка Решения.** Создать гипотезу по формуле Класса Б. Обязательно указать выгоды.
- [ ] **Шаг 4: Дизайн исследования (CustDev).**
    - Определить тип исследования (Проблемное или Решенческое интервью).
    - Оценить размер выборки.
    - Сформулировать "валидирующий вопрос" (на базе реальных действий: "А что вы для этого уже сделали?").
    - Составить список вопросов по сценарию (напр. Сценарий Замесина или Базовая структура).
- [ ] **Шаг 5: Критерии успеха и критерии оценки.**
    - Определить количественный порог подтверждения (напр. >40% по тесту Шона Эллиса).
    - Прописать логику интерпретации.

## 4. Heuristics (Эвристики)
- **Фокус на действиях:** Если пользователь не пытался решить проблему раньше — проблемы не существует.
- **Потери и Выгоды:** Гипотеза без цифр (потерь/выгод) — это галлюцинация, а не бизнес-гипотеза.
- **RAT (Riskiest Assumption Test):** Всегда начинать проверку с самого рискованного предположения.
- **Цветовое кодирование (из CJM):** Проблемы — Красный, Задачи — Желтый, Выгоды — Зеленый.

## 5. Формат вывода (Таблица гипотез)

Каждое исследование должно быть представлено в виде таблицы со следующими колонками:

| # | Гипотеза Проблемы (Класс А) | Гипотеза Решения (Класс Б) | Выборка | Метод оценки | Confidence (1-10) | Base % (0-100) | WTP (1-10) | Score |
|---|-----------------------------|----------------------------|---------|--------------|-------------------|----------------|------------|-------|
| 1 | "Мы считаем..."             | 1.1 "Мы считаем..."        | n=...   | [Метод]      | ...               | ...            | ...        | ...   |
|   |                             | 1.2 "Мы считаем..."        | n=...   | [Метод]      | ...               | ...            | ...        | ...   |

### Формула Score:
`Score = Confidence * (Base % / 100) * Willingness to Pay (WTP)`

### Справочник методов оценки:
- **Глубинное интервью** (проблемное/решенческое)
- **Короткий CustDev** (в контексте процесса)
- **UX-тест / Юзабилити-тестирование**
- **A/B тест** (количественная проверка)
- **Коридорное исследование** (быстрая проверка на коллегах/случайных людях)
- **Fake Door Test** (кнопка-пустышка для проверки спроса)
- **Анализ данных (Quant)**
- **Опрос (Survey)**

## 6. Templates & Examples

### Пример дизайна исследования
- **Выборка:** n=30 представителей целевого аватара.
- **Вопросы:**
    1. Расскажите, как вы сейчас решаете задачу Х?
    2. Что является самым сложным в процессе Y?
- **Критерии оценки:** Гипотеза подтверждена, если >60% респондентов подтвердили наличие проблемы Х.
